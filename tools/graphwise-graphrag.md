# Graphwise GraphRAG

Graphwise GraphRAG combines components of a semantic application stack. Graph Modeling, formerly PoolParty, contributes vocabulary and semantic foundations; GraphDB contributes graph capabilities; GraphRAG workflows connect queries, vector search, and answer generation. The exact release and component configuration define the implemented application.

## Documented capabilities and boundaries

Graph-grounded answers combining semantic modeling, graph queries, vector search, and conversational workflows. [Primary evidence](https://help.graphwise.ai/gwp26-1/en/graphrag.html).

A meaningful evaluation separates the governed semantic assets from the populated graph and the evidence returned for a question. Shared platform integration is valuable only if users can understand which definitions, records, and passages support the response.

## Place in an implementation

An illustrative pilot could connect a controlled taxonomy and graph to a small document collection, ask a domain question, and inspect concept expansion, graph queries, retrieved passages, and the final answer. Change a term or source fact and trace its impact.

## Dependencies and scope

Graph Modeling and GraphDB contribute separate roles. Record separately which component defines meaning, populates facts, selects evidence, and generates answers. Shared branding or database support does not establish a working integration.

## What to verify in an evaluation

- Which Graph Modeling, GraphDB, workflow, and service versions form the supported configuration, and how are their changes coordinated?
- Distinguish the semantic definitions, populated entity facts, retrieval result, and generated response in a demonstration.
- Trace a claim back to the source and show how a change in meaning, identity, or source data reaches the answer.
